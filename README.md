# mpv-build

[![mpv](https://img.shields.io/badge/mpv-v0.41.0-blue.svg)](https://github.com/mpv-player/mpv)
[![ffmpeg](https://img.shields.io/badge/ffmpeg-n8.0.1-blue.svg)](https://github.com/FFmpeg/FFmpeg)
[![license](https://img.shields.io/github/license/edde746/mpv-build)](https://github.com/edde746/mpv-build/blob/main/LICENSE)

Patched `libmpv` and FFmpeg binaries for the apps Plezy and Tortuga ship, built
from one set of pins and patch series:

| Platform group | Artifact |
| --- | --- |
| apple | XCFrameworks for iOS, tvOS, macOS, Mac Catalyst and the iOS/tvOS simulators, as the SwiftPM product `MPVKit` |
| android | `libmpv-android-<key>-<abi>.tar.gz` per ABI, and the `mpv-android-<key>.aar` library |
| linux | `libmpv-linux-<key>-<arch>.tar.zst` (x86_64, aarch64) |
| windows | `libmpv-windows-<key>-<arch>.zip` (x86_64, aarch64), the mpv-dev package shape |

Every push to `main` publishes the binaries that commit needs, so any commit on
`main` can be pinned. Each publish run uploads what it built to a prerelease of
its own, `binaries-<first 12 hex of the commit built>`. Assets published before
that stay where they are, in
[`binaries-apple`](https://github.com/edde746/mpv-build/releases/tag/binaries-apple),
[`binaries-android`](https://github.com/edde746/mpv-build/releases/tag/binaries-android),
[`binaries-linux`](https://github.com/edde746/mpv-build/releases/tag/binaries-linux) and
[`binaries-windows`](https://github.com/edde746/mpv-build/releases/tag/binaries-windows),
which take nothing new.

## Layout

| Path | Purpose |
| ---- | ------- |
| `versions.json` | Every component pin (version, URL, hash or commit), with per-platform overrides; a prebuilt's `upstream` names the source commit it was built from. |
| `patches/<component>/` | Patch pool and series files; see [Patches](#patches). |
| `toolchain/<group>.txt` | Toolchain pins and the generation that forces a group's full rebuild. |
| `artifacts.json` | The published binaries, one section per platform group. Written by CI. |
| `Package.swift` | SwiftPM manifest, rendered from the apple section of `artifacts.json`. Written by CI. |
| `Sources/BuildScripts/` | The Apple build driver (`make build`). |
| `Sources/_MPVKit/licenses/` | The licence texts of everything the Apple package links, generated by `scripts/licenses.py apple`. |
| `platforms/<group>/` | The android, linux and windows drivers, each defined by its `group.json`. `platforms/android/lib/` is the mpv-android library. |
| `scripts/` | `patches.py` (series), `keys.py` (content keys and the publish gate), `licenses.py` (licence texts), `symbols.py` (debug symbols), `extract.py` (code slicing for tests), and the regression tests. |
| `docs/` | [Apple](docs/apple.md) and [Android](docs/android.md) details. |

## Using it

**SwiftPM.** Add `https://github.com/edde746/mpv-build.git` and pin a commit (in
Xcode, `Branch/Commit` → the SHA). The product is `MPVKit`. Semver tags
exist but carry no assets of their own. Consumer notes (pkg-config, AVPlayer
passthrough, spatial audio): [docs/apple.md](docs/apple.md).

**Android AAR.** Resolve `edde746:mpv-android:<key>@aar` through an Ivy
repository on the AAR's release URL; the key, sha256 and release come from
`artifacts.json`. Setup, API and helpers: [docs/android.md](docs/android.md).

**Linux and Windows.** Download the asset named in `artifacts.json`
(`platforms.<group>.libraries.libmpv-<group>.prebuilt.<arch>`) from its
location (below) and check its sha256. The Windows zip has `libmpv-2.dll`,
`libmpv.dll.a`, `include/mpv/*.h` and `licenses/` at its root
([platforms/windows/README.md](platforms/windows/README.md)). The Linux tarball
holds `lib/`, `include/` and `licenses/`, built in the container
`toolchain/linux.txt` pins (glibc 2.39).

**Pinning a commit.** A consumer pins one commit of this repository and reads
that commit's `artifacts.json` for every non-SwiftPM asset. Assets are
content-addressed: the 12-character key in each name is derived from the
component pins, the resolved patch series, the build flags, the platform
tuple, the build driver and the toolchain file. A published asset never
changes, and is never deleted while a commit's manifest points at it.

An unchanged library keeps the assets an older run built, so one commit's
assets can sit in several releases, and the manifest records each asset's
location: its URL is `<assetBase>/<asset>`, with the `assetBase` beside the
asset's name (`prebuilt.<variant>.assetBase`, `symbols.<variant>.assetBase`, or
a package entry's own `assetBase`) or, when it has none, the group section's
`platforms.<group>.assetBase` (the old `binaries-<group>` release).
Package.swift already spells out each framework's full URL.

## Updating

1. A change lands on `main` (from a pull request; `ci.yml` runs the patch
   checks, the host regression tests, the android build and the Demo apps).
2. `publish.yml` computes each group's keys, builds only what is not published
   (`keys.py stale`), uploads what it built to the run's own release
   `binaries-<sha>`, and records each asset with that release as its location.
   A run that never commits its manifest leaves a release nothing points at;
   the next run deletes it before opening its own.
3. It then commits `artifacts.json` and `Package.swift` to `main` as
   `chore: binaries for <sha> [skip binaries]`. That binaries commit is the one
   to pin: the commit before it has no manifest entries for its new assets.
4. A consumer moves its pin to the binaries commit. Tortuga does it with
   `tools/set_native_revision.sh <sha|latest>`, which rewrites its
   `mpv-build.lock.json`, Gradle verification metadata and Apple project.

```bash
python3 scripts/keys.py keys --platform-group apple     # what this tree needs
python3 scripts/keys.py stale --platform-group apple    # what is not published yet
python3 scripts/keys.py verify --platform-group apple   # manifest matches this tree
```

A change to `patches/mpv/*` moves libmpv's key alone; editing a group's build
driver moves every key in that group. To force a rebuild without a source
change (a new Xcode, a miscompile), bump `generation` in that group's
`toolchain/<group>.txt`. `check_version.yml` opens weekly pull requests that
move the mpv and FFmpeg pins (and the badges above) and the prebuilt
dependencies to new upstream tags. `release.yml` tags a commit whose
`Package.swift` passes `verify`; it builds nothing. Each pin's `provenance` in
`versions.json` says why it is pinned; Windows' `fontconfig` pin is temporary
and goes once winbuild rebases its fontconfig patches.

## Building locally

**Apple** (macOS, Xcode selected with `xcode-select`, [rustup](https://rustup.rs)):

```bash
rust_version="$(sed -n 's/^rust=//p' toolchain/apple.txt)"
rustup toolchain install "$rust_version" --profile minimal --no-self-update \
  --component rustc,cargo,rust-std \
  --target aarch64-apple-ios,aarch64-apple-ios-sim,x86_64-apple-ios,aarch64-apple-tvos,aarch64-apple-tvos-sim
make build                          # every platform
make build platform=ios,macos       # ios,macos,tvos,tvsimulator,isimulator,maccatalyst,xros,xrsimulator
make build libs=libmpv use-prebuilt # compile libmpv, restore the rest from published binaries
make help
make clean
./mpv.sh [url]                      # the mpv player from a macOS build
```

Output lands in `dist/`. Repeat the rustup step when `toolchain/apple.txt`'s
`rust` pin changes.

**Android:**

```bash
bash platforms/android/include/download-sdk.sh
bash platforms/android/download.sh
bash platforms/android/build.sh --arch arm64
bash platforms/android/package.sh --arch arm64
bash platforms/android/lib/build-aar.sh --tarballs dist/release
```

See [docs/android.md](docs/android.md) for the prerequisites and rebuild rules.

**Linux** (docker; the published path, in the container `toolchain/linux.txt` pins):

```bash
KEY="$(python3 scripts/keys.py keys --platform-group linux \
  | python3 -c 'import json, sys; print(json.load(sys.stdin)["libmpv-linux"])')"
KEY="$KEY" ARCH=x86_64 bash platforms/linux/container-build.sh
```

Without `KEY` it builds but does not package; the script's header lists its
other variables.

**Windows** (Linux host): `platforms/windows/build.sh <x86_64|aarch64>` then
`platforms/windows/package.sh <x86_64|aarch64>`; host requirements are in
[platforms/windows/README.md](platforms/windows/README.md).

## Patches

Each patched component (mpv, ffmpeg, libass, libplacebo, libdovi) keeps one
platform-neutral pool and per-platform series files. Line order is the
application order, and each patch's header explains it.

```
patches/<component>/pool/<name>.patch   the patch bytes
patches/<component>/series.common       applied on every platform, first
patches/<component>/series.<platform>   applied after series.common
```

```bash
python3 scripts/patches.py check                                 # pools, series and versions.json agree
python3 scripts/patches.py resolve mpv apple                     # one platform's ordered series
python3 scripts/patches.py apply mpv apple <srcdir> --check      # the series still applies
python3 scripts/patches.py fetch-pinned mpv apple <srcdir>       # fetch the pinned source and apply
```

`fetch-pinned` checks a `git` pin's commit or an `archive` pin's sha256 before
applying. `ci.yml` applies every nonempty series to its pinned source, so a
version bump that breaks a patch fails before anything builds.

## Debug symbols

The android, linux and windows groups publish one debug-symbols zip per variant
beside each binary, so a crash tracker can symbolize libmpv and FFmpeg frames.
Each zip holds, at its root, the debug files of what that variant ships,
matched by identity (ELF GNU build-id, or a DLL's CodeView GUID and age), never
by name.

| Group | Asset, per variant | Contents |
| --- | --- | --- |
| android | `mpv-android-<key>-<abi>-symbols.zip` | a debug ELF for every `.so` in the AAR's `jni/<abi>/` (`libc++_shared.so` only when the NDK has its unstripped copy) |
| linux | `libmpv-linux-<key>-<arch>-symbols.zip` | a debug ELF for every shared library in the tarball |
| windows | `libmpv-windows-<key>-<arch>-symbols.zip` | `libmpv-2.pdb` |

They are recorded under the artifact's `symbols` entry in `artifacts.json`, and
`keys.py` treats an entry without every variant's symbols as unpublished.
`scripts/symbols.py` is the only packer:

```bash
python3 scripts/symbols.py id libmpv-2.dll libmpv-2.pdb          # identities, as the tracker spells them
python3 scripts/symbols.py match <shipped> <candidate>...       # the matching candidate with the most debug info
python3 scripts/symbols.py pack out.zip --pair <shipped> <debug>  # checked, reproducible zip
```

### Licence texts

Every artifact carries the licence texts of each component linked into it, as
`licenses/<component>/<path in that component's source>`, copied unchanged from
the source the build compiled. `scripts/licenses.py` holds the per-component
rules (vendored subtrees, licence comments cut out as `<file>.txt`, the licence
files of every Rust crate linked).

| Artifact | Where | Components |
| --- | --- | --- |
| `libmpv-linux-<key>-<arch>.tar.zst` | `licenses/` | the `components` of `platforms/linux/group.json` |
| `libmpv-android-<key>-<abi>.tar.gz` | `licenses/` | the `components` of `platforms/android/group.json`, `libc++` (the NDK's) and `rust-std` (in libdovi) |
| `mpv-android-<key>.aar` | `assets/licenses/`, so they reach the app's APK | the tarballs' texts (identical for every ABI), and `mpv-android/`: the glue's `NOTICE` and this repository's `LICENSE` |
| `libmpv-windows-<key>-<arch>.zip` | `licenses/` | every package linked into `libmpv-2.dll`, named as in `versions.json` where it pins one, else by its mpv-winbuild-cmake package name |
| MPVKit (SwiftPM) | `MPVKit__MPVKit.bundle/licenses/` in every app (the `_MPVKit` target's resources) | every `versions.json` component whose `platforms` include `apple`, and `rust-std` |

- Linux, Android and Windows collect the texts while building, and packaging
  runs `licenses.py check`: the artifact must hold exactly one non-empty folder
  per linked component. A text that moved upstream fails the build.
  `licenses.py` is a driver of those groups, so changing it moves their keys.
- Apple: most XCFrameworks are prebuilts that carry no text, so
  `licenses.py apple` fetches every Apple component at the commit it was built
  from (a prebuilt's `upstream` in `versions.json`), adds `rust-std` from the
  toolchain `toolchain/apple.txt` pins, and writes `Sources/_MPVKit/licenses/`,
  which is committed. CI's `Apple licence texts` job fails if it differs. After
  changing an Apple pin, an `upstream` or a rule, regenerate it (needs git,
  network and that toolchain through rustup):

```bash
python3 scripts/licenses.py apple          # rewrite Sources/_MPVKit/licenses/
python3 scripts/licenses.py apple --check  # what CI runs
```
